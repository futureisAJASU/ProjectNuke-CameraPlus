## True process-cold: how it is actually proven

True process-cold is proven by the HOST, not by app-side test-method separation. Separating
test methods inside the app does NOT by itself prove the app process is cold between
invocations. For every invocation (SEED, each OFF/ON, ZERO-WRITE, FINAL-SWEEP) the host
orchestrator:

1. records that the previous instrumentation command has exited (`prevInstrumentationExitStatus`),
2. runs a bounded process query BEFORE force-stop (`pidof <pkg>` and `ps -A | grep -F <pkg>`),
3. issues the exact `am force-stop <pkg>` command and records its exit status,
4. runs a bounded process query AFTER force-stop,
5. requires the target process to be ABSENT after force-stop. A run is INVALID if the
   process is still present. Command success alone is NOT treated as process absence.
6. launches one fresh `am instrument -w` invocation and records its exit status.

## Volume generation changes

If unrelated real MediaStore activity changes volume generation during a run, the affected
run records its rejected/fallback counters honestly. Unrelated user media is never deleted or
manipulated to force a quiet volume. A repeat under a later quiet window is allowed; a
rejected attempt is retained in the evidence. In the committed run all six comparison runs
were clean (OFF 46/0, ON 46/0).

---

## Zero-write verification

For every paired run, each exact job directory is fingerprinted before and after using
content hashes (SHA-256), not timestamps. All 46 job directories were content-byte-identical
in both modes (`invariants.allPairedZeroWrite = true`).
